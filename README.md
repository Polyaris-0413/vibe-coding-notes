## AGENTS.md
> 该提示词包含许多个性化条目，且需搭配上述技能使用，并不适合所有人。
```text
# 全局开发规范

> 本文件仅作为已安装技能的补充，不重复已有规则。  

> 规则冲突时，应询问用户处理方案。

> 本文件未特殊说明的条目，一律为强制规则。

## 0. 沟通

- 思维链与正文应使用中文。
- 应严格按用户指令执行，不得有语义漂移，即使你认为结果相同。
- 未经询问，不得对已有功能做用户可见的取舍。

## 1. 技能调用

- 任务开始时，应先调用 `using-superpowers`，以确定所需技能。

## 2. 减少冗余

- 实现功能前，应先检索项目内可复用代码；若有，应直接调用。
- 若调用不便，应封装为函数/方法后再调用，不得复制粘贴重写。
- 无现成代码时，应按优先级选择方案：`语言/框架原生 API > 成熟第三方库 > 自行实现`。

## 3. 长期思维

- 应采用最适合项目的标准化方案。
  > 若用户决策与此不符，应暂停任务，说明原因、给出方案并询问意见。
- 不得为快速实现采用临时方案。

## 4. 注释

- 注释应仅写代码无法表达的原因与出处。
- 不得“达到预期”式复述，也不得保留与代码不符的过时注释。

## 5. 漏洞修复

- 非必要不使用补丁，应从源头解决问题。
- 若确需补丁，应覆盖所有同类变体，而非仅当前样本。

## 6. 设计

- 所有设计类取值应来自项目统一的设计源，代码只引用，不得另行定义。
  > 设计源包括项目所采用的公共设计语言规范  
  > 若项目尚无设计源，应先建立最小设计源再实现功能。

## 7. 交付

- 编写 Android 项目时，每次交付后应编译、安装并打开应用。

## 8. 备份

- 每次代码修改后，应将文件备份至 Git。
- 用户要求回滚代码时，应使用 Git 回滚，不得凭记忆复原。
```
